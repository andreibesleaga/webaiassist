# Accessibility

The target is WCAG 2.2 level AA for the side panel, the confirmation dialog and the Options
page. Two automated checks run in `npm run verify:release` and in CI; a screen-reader test has
not been done yet.

## How it is checked

| Check                         | Where                            | Runs                                                                                                                                            |
| ----------------------------- | -------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| axe-core in jsdom             | `test/ui/a11y.test.ts`           | Unit tests; every rule except colour contrast (jsdom has no layout)                                                                             |
| axe-core in Chromium          | `test/smoke/a11y.spec.ts`        | The built extension; WCAG 2.0, 2.1 and 2.2 A and AA rules, contrast included                                                                    |
| Keyboard-only run in Chromium | `test/smoke/a11y.spec.ts`        | Tab order, visible focus, Help, the dialog, Options, Save                                                                                       |
| axe-core on each state        | `test/smoke/a11y-states.spec.ts` | Light and dark: card with tools list and More open, node page, blocked site, error banner, download question, welcome screen, Options at 320 px |
| Names, order, motion, zoom    | `test/smoke/a11y-states.spec.ts` | Card names, toggle behaviour, reduced motion, 200 percent zoom of a 480 px panel                                                                |
| Contrast from the tokens      | `test/ui/contrast.test.ts`       | Every colour pair of `static/ui.css`, light and dark, computed with the WCAG formula                                                            |

Browser: headless Chromium 156 from Playwright 1.64.1; axe-core 4.14.0. The side panel page is
opened in a tab, as the smoke test does; a 320-pixel-wide window stands in for a narrow panel.

## Found and fixed by these checks

- The model list was wider than a 320-pixel panel and made the page scroll sideways. Lists now
  shrink to the panel width.
- The conversation scrolls in a narrow panel, but a keyboard user could not reach it. It is now
  a focusable region, so arrow keys scroll it.

## Other points

- Streamed answers go into a polite live region (`role="log"`); the text being typed is hidden
  from screen readers until it is complete.
- Status lines (model, page, Options) use `role="status"`.
- Motion: with the system setting "reduce motion", the stylesheet turns animations and transitions off.

## Welcome screen, download question and error banner (14 Nov 2026)

The welcome screen (focus on its title on the first run, then Got it and Choose another model in
Tab order) is axe-clean in `test/smoke/a11y.spec.ts`. The download question moves the focus to

## The redesigned panel and Options page (14 Nov 2026)

Tokens, light and dark. All colours are tokens at the top of `static/ui.css`. The unit test
`test/ui/contrast.test.ts` reads them and computes the WCAG ratio of every pair the stylesheet
uses: 15 text pairs at 4.5:1 or more and 6 outline or focus-ring pairs at 3:1 or more, in both
themes (weakest text pair: the accent colour on the light blue tint, 5.57 in the light theme; weakest outline: the control border on a card, 3.82 light and 4.99 dark). Changing a colour that breaks a pair fails the test.

What the new parts do for assistive technology:

- The page card is a `section` named by its heading (the site's host, or "This page"). The
  access badge says in words what WebAIAssist may do: No page, Cannot run here, Not allowed yet,
  Allowed, Blocked by the site. Colour is never the only signal.
- The tools toggle is a button with `aria-expanded` and `aria-controls`; opening the list keeps
  the focus on it. Each tool shows its name, a mark in words ("reads", "changes", "not marked",
  "page content") and one line of what it does. A tool that may change something also has a "!"
  sign (hidden from screen readers; the word carries the meaning).
- The same sign stands beside the warning of the "Run the tool?" dialog.
- `#page-status`, `#model-status` and `#page-note` are polite status regions, the error banner
  is an alert, the conversation is a log. The model status line changes once per ten percent
  while a model downloads; the progress bar itself moves on every step. The streaming draft is
  `aria-hidden`; the finished answer enters the log once.
- Assistant answers carry the label "AI" (drawn from an attribute so the plain name stays
  "WebAIAssist") and a permanent line says that answers come from an AI model and can be wrong.
- Reduced motion: transitions and animations are off, and the waiting bar becomes a still, full
  bar. Forced colours: badges, chips, marks, buttons and the card get a system-colour border.
- 200 percent zoom of a 480 px panel (a 240 px layout) and 320 px width: no sideways scroll, no
  clipped text (the one-line page title is cut with an ellipsis on purpose and shows in full as
  its tooltip).

Still not tested: a screen reader, the real side panel frame, 400 percent zoom, Windows
high-contrast mode (the forced-colours rule is written, not checked by hand).

## The graph explorer tab (14 Nov 2026)

`test/smoke/explorer-safety.spec.ts` runs the axe-core WCAG 2.2 A and AA rules (`test/smoke/a11y-helpers.ts`)
on `explorer.html` with the node's graph drawn and the peers block shown, in the light and the dark
theme: no violation in either (colour contrast included), and on the side panel with the "Graph: N
items" button in both themes (`test/smoke/explorer.spec.ts`). The site's explorer was built for this: the
picture is `aria-hidden`; every node is also a button in a list; the status line is `role=status`, a polite
live region announces selection; the width separator has arrow, Home and End keys; Escape clears the
selection. What the page adds around it:

- `lang`, one `main`, one `h1` (the text "Graph of", then the host), a skip link first that goes to the
  list of nodes, a tab list (`role=tablist`, arrow keys, Home and End move between tabs, one tab in the tab order).
- The site's node field, Load button, Peers box, 2D and 3D buttons and the rotate button are hidden with
  `display:none`, so they are neither visible nor in the tab order. Other nodes have their own block with one
  labelled checkbox each and one button; a node that cannot be ticked shows why in words.
- A digest mismatch is a `role=alert` line; the "no graph" note is a `role=status` line.
- Colour tokens are the site's, defined in `static/explorer.css` for both schemes; focus rings use the
  focus token. The site's CSS wraps the controls at narrow widths and gives 44-pixel targets on
  small screens; `prefers-reduced-motion` is read by the site's code.

Not tested: a screen reader on the canvas alternative (the button list), page zoom to 200 percent of the
explorer (the panel's own 200 percent test is above).
