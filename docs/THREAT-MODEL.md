# Threat model

> **In short**
>
> - The web page, its tools and the model output are not trusted. Every tool call goes through the confirmation gate, and the default mode asks before every call.
> - The extension has no install-time host access, no `web_accessible_resources` and no `externally_connectable`.
> - An independent review on 12 Nov 2026 led to 15 findings and four information items, all fixed; every test in `test/security-review/` passes.
> - Residual risks include: a site's tool cannot be checked, a small model can be steered, the endpoint key is stored unencrypted, and weight shards are not hash-checked.
> - Not tested here: a screen reader, browsers other than Chromium, and a real model in CI.

What WebAIAssist protects, where the trust boundaries are, how each threat is handled, and
what remains. Every control names the file that implements it and the test that proves it.
Version 0.1.0, 13 Nov 2026.

## Assets

- The user's control over actions: no page tool runs without the rule the user set.
- The conversation, the page text read, tool results and memory (chat and tool counts per
  site).
- The endpoint address and API key in Options.
- The integrity of the code that runs, the model library included.

## Trust boundaries

| Part                       | Runs where                     | Trusted? | Why                                                                                                                           |
| -------------------------- | ------------------------------ | -------- | ----------------------------------------------------------------------------------------------------------------------------- |
| Web page and its tools     | The page's own world           | No       | Any site; it writes the tool names, descriptions, schemas, hints, results                                                     |
| MAIN-world script          | Inside the page's world        | No       | The page can see it, call it and imitate its messages; it answers only messages whose source is its own window, never a frame |
| Isolated content script    | The tab, extension's own world | Partly   | Extension code, but everything it relays from the page is untrusted data                                                      |
| Service worker             | Extension                      | Yes      | Accepts messages only from extension pages; routes to the top frame only                                                      |
| Offscreen document (model) | Extension                      | Yes      | Runs the model; accepts the model port only from extension pages                                                              |
| Side panel                 | Extension                      | Yes      | Agent loop, gate, memory, export                                                                                              |
| Model output               | Model host                     | No       | A small model can be steered by text it read; its reply is parsed and checked                                                 |
| Chat endpoint              | The address the user set       | No       | Receives the conversation; its reply is treated like any model output                                                         |
| Model weights host         | huggingface.co, `*.hf.co`      | Partly   | HTTPS and a fixed revision; config and tokenizer hash-checked; weights are data                                               |

## Site files and the page card (14 Nov 2026)

The panel follows the open tab by itself and, for a site the user has allowed, reads the public

Decisions, with the reason:

- The reads run in the tab, not in the service worker. A service worker request would carry the
  extension's origin and could reach any granted host if a bug built a wrong address. A tab
  request is same-origin by construction. A measured test shows that a page policy with
  `connect-src 'none'` does not stop it.
- Redirects are refused, so a file cannot send the read to another host. The cost is a few sites
  whose well-known file redirects within the site; the file then counts as unavailable.
- The MCP server card is not read: its path is not settled (13 Nov 2026). The skills index named
  by a node's link set is NOT read: its address would come from a file. (An earlier research note
  said it could be read; this decision stands until a later package changes it and this line.)
- The cap was eight files (research note, rule F4). On 14 Nov 2026 the maintainer approved exactly one
  more, `/.well-known/sustainability-data`: a fixed path, JSON, at most 8 KiB, read as data only.
  `api-catalog` and `agent-card` are kept. The reason and the cap sit in `src/core/site-files.ts`.
- Digests: for a file that the node's own knowledge links list with a `sha-256` digest, the page
  script hashes the raw bytes and the panel compares. A file that differs is marked and is not
  given to the model (`robots.txt` and `tdmrep.json` are never dropped, so a "no AI" statement is
  never ignored). A match is worded "matches the node's own list": the same site publishes both,
  so it shows the files are unchanged since the node published its list, not who wrote them.
- The sustainability file's signature is shown only as "present"; it is not checked.
- `Content-Signal` values of every `robots.txt` group are shown. Only the `*` group decides "no AI
  input" (pinned by `test/core/site-node-extras.test.ts`).
- "Copy diagnostics" builds its text from fixed fields only (`src/core/diagnostics.ts`); the
  endpoint key and addresses are removed from the error text; the preview is the copied text.
- The one manifest key added: `commands` with `_execute_action` (keyboard shortcut for the
  toolbar button, suggested Alt+Shift+A). It needs no permission, adds no host and runs the
  existing toolbar-click handler. Approved by the maintainer on 14 Nov 2026; `scripts/check-dist.mjs`
  refuses any other command.
- A `robots.txt` that cannot be read counts as "not stated", so a site outage does not turn the
  assistant off.
- Not done: a tool result marked `untrustedContentHint` is still given to the model when a site
  asks for no AI input. The tools of the site stay usable and go through the confirmation gate.
  The panel and `docs/PRIVACY.md` say so (audit L3, 14 Nov 2026): the site's text and files are
  held back, results of its own tools are not.

## Why the manifest has no `connect-src` list

The extension pages' policy limits scripts only (`script-src 'self' 'wasm-unsafe-eval'`). There is
no `connect-src` list, and this is deliberate. The hosts the code may contact are not fixed in
advance: the model weights redirect from `huggingface.co` to a download host that Hugging Face
chooses by region, and the chat endpoint is an address the user sets. A list that allowed both
would have to allow every `https` address, so it would add no protection; a short list would
break downloads or endpoints. The limit is in the code instead: the weight addresses are fixed
and carry a recorded SHA-256, the endpoint must be `https` or `http` on localhost, redirects of
the endpoint are refused, and `docs/PRIVACY.md` lists every host (a test compares it with the
built files).

## Residual risks

- **A site's own tools.** The extension shows the tool, the site and the arguments, but cannot
  know what the tool does. In "once per site per session" mode, a tool the page falsely marks
  read-only runs without a question. The default mode asks every time.
- **A small model can be steered.** Page text can still change what the model answers, even
  though it cannot run a tool past the gate. Answers are only as reliable as the page.
- **The processor models read the whole file once to hash it.** A 1.1 GB or 1.3 GB file needs as much
  free memory for that check; if the browser cannot give it, the load stops with an error and the
  file stays unchecked and unused. The 0.6B file (397 MB) was hashed in the measured run.
- **wllama's cache may use Chrome's cross-origin file storage** when Chrome has it
  (`navigator.crossOriginStorage`, absent in Chromium 156). Files there are keyed by their
  SHA-256, so another site could learn that a file with that hash exists. The extension does
  not turn it off (wllama gives no switch short of our own storage code); the files are public
  model files, not user data.
- **Weight shards are not hash-checked.** They come over HTTPS from a fixed revision of the
  `mlc-ai` repositories; WebLLM 0.2.86 can hash-check the model library, the config
  (`mlc-chat-config.json`) and the tokenizer, and all three are pinned, but it has no hash
  option for the weight shards. Tampered weights could give wrong answers, but they are data
  and cannot run code.
- **The default model rests on one measurement.** The first answer after a load on this graphics
  card decides whether it may be the default (20 seconds); a one-off slow or fast first answer
  changes the default until the next measurement. The user's own choice is never overridden.
- **Forget all sites keeps the endpoint's host access.** That access is by host name, not port, so
  it can cover other `localhost` pages; it is not used for tool listing or file reads there, because
  those need the site to be on the list of allowed sites. Reset to defaults removes it; so does
  `chrome://extensions`.
- **The endpoint key is stored unencrypted** in `chrome.storage.local`, readable by anyone
  with access to the browser profile. Content scripts cannot read it
  (`setAccessLevel('TRUSTED_CONTEXTS')`).
- **Pattern check is a heuristic.** A page's schema `pattern` that is long, repeats a group
  that itself repeats or offers alternatives, or has three quantified atoms in a row is refused
  before it runs; a pattern that backtracks badly in another way could still slow the panel.
- **Token counts are estimates.** Three Latin characters per token and one per other
  character; a tokenizer that splits text more finely could still overflow the window.
- **The processor models are slow.** Measured 14 Nov 2026 on 8 threads: about 11 tokens a
  second for the reply and about 20 for the prompt (the first question reads the rules and the
  tool list, about 900 tokens, in about 40 seconds; later questions reuse that part). The 1.7B model
  is about half as fast. They need
  Chrome 137 or newer.
- **The model host in a Worker is not yet measured on a GPU.** The offscreen document now runs
  WebLLM in a dedicated Worker; WebGPU in that Worker was not checked on real hardware in this
  round (the probe still runs in the document).
- **A site can say it is an AgenticSystemCore node.** The node mode adds a hint about the roles of
  the ten tool names; the site writes those tools. The hint no longer claims what they do, and
  the gate is unchanged (audit L1).
- **Saved assistant turns come back unchanged.** Tool turns are fenced again on load; an answer
  that repeated page text is replayed in the assistant role. The gate holds either way.
- **The MAIN-world script is visible to the page.** It holds no secret; the page can read the
  channel id and answer for itself, which gives it nothing it does not already have.
- **Development tools** have open advisories (Vitest and markdownlint dependencies) whose fixes
  are major versions; they are not part of the package.
- **Not tested here:** a screen reader, browsers other than Chromium, a real model in CI.

## Conformance page and demo pages (14 Nov 2026)

- The hostile cases (instructions in a description, hidden text, look-alike names, a name like the
  planned built-in tool) are test fixtures. They run only on the conformance page under
  `conformance/`, which is not part of the extension package: `scripts/build.mjs` and `scripts/zip.mjs`
  do not name it and a test checks that.
- The eval build made with `--demos` has one more install-time host, `googlechromelabs.github.io`.
  It exists only in `dist-eval/`; `scripts/check-dist.mjs` accepts it only for that build and the
  release check still refuses every install-time host (`test/scripts/check-dist.test.ts`).
- Google's demo pages are third-party pages: their tools are untrusted like any page's. The demo run
  uses the normal confirmation, calls only a tool the page marks read-only that needs no argument,
  and never submits a form.
- The conformance page sends nothing: it has no network call and no analytics (a test checks the
  folder for `fetch`, sockets and outside hosts).
